### 模块一

1. **A**。`i = i++` 先把 `i` 的旧值 0 赋给临时变量，再自增到 1，最后把临时变量 0 赋回 `i` → 0。经典陷阱。
2. **C**。`switch` 支持 `byte/short/char/int`、`String`（1.7+）、`enum`；**不支持 `long/float/double/boolean`**。
3. **B**。`b + 1` 自动提升为 `int`，赋回 `byte` 需强转：`b = (byte)(b + 1);`。
4. **B**。从左到右：`1+2=3`（int）→ `3+"3"="33"` → 之后全是字符串拼接 `"331"+"2"="3312"`。
5. **C**。`float` 数组默认值是 `0.0f`（打印为 `0.0`）。`int[]` 才是 0。
6. **B**。`for` 初始化块里声明的变量作用域仅限该循环。
7. **A**。`Integer` 缓存 `-128~127`，127 在缓存内，两个引用指向同一对象 → `==` 为 `true`。
8. **B**。128 超出缓存范围，各自 `new` 一个对象 → 地址不同 → `false`。比较 `Integer` 永远用 `equals`。

### 模块二

9. **C**。只有返回值不同**不构成重载**（调用时无法区分），编译器直接报错。
10. **B**。抽象类可以有构造方法，供子类 `super(...)` 调用，只是不能 `new` 自己。
11. **A**。接口字段隐式 `public static final`，必须初始化。
12. **B**。编译看左边（能调 `sound`），运行看右边（执行 `Dog` 的实现）——这就是多态。
13. **B**。`static` 方法属于类，子类同名方法是**隐藏**，不参与多态；用父类引用调用仍执行父类版本。
14. **B**。父静态 → 子静态 → 父实例块/父构造 → 子实例块/子构造。（静态只加载一次）
15. **B**。JDK 8 起只需 effectively final（不必显式写 `final`），本质是**值捕获**（拷贝）。
16. **B**。`final` 锁的是**引用**不能变，对象内容仍可改。`list.add()` 合法。

### 模块三

17. **A**。`ArrayList` 默认 `DEFAULTCAPACITY_EMPTY_ELEMENTDATA`，首次 `add` 才扩到 10；之后扩容 `oldCapacity + (oldCapacity >> 1)` = 1.5 倍。
18. **A**。容量 16、负载因子 0.75、链表长度 ≥8 且数组长度 ≥64 时转红黑树（不足 64 先扩容）。
19. **B**。`UNTREEIFY_THRESHOLD = 6` 时退化回链表（8 转树、6 退链，留 2 的缓冲防抖动）。
20. **C**。只重写 `equals` 会导致 hash 不同、落不到同一个桶里，`get` 永远拿不到。规则：**equals 相等则 hashCode 必须相等**。
21. **B**。`foreach` 用的是 `Iterator`，`list.remove` 修改 `modCount` → 迭代器 `checkForComodification` 抛 `ConcurrentModificationException`。正确做法：`Iterator.remove()` 或 `removeIf`。
22. **B**。`ArrayList` 底层数组，随机访问 O(1)；`LinkedList` 是 O(n)。
23. **B**。`HashSet` 内部 `private transient HashMap<E,Object> map`，值统一放一个 `PRESENT` 占位对象。
24. **C**。`TreeSet` 底层 `TreeMap`，靠 `compareTo` / `Comparator` 排序；与 `hashCode`/`equals` 无关。

### 模块四

25. **C**。`IOException` 及其子类（除 `RuntimeException` 分支）是受检异常；A、B、D 都是 `RuntimeException` 子类。
26. **B**。`finally` 一定执行，只有 `System.exit()`、JVM 崩溃、断电等极端情况例外。
27. **B**。`finally` 里的 `return` 会**覆盖** `try` 里的 `return`（还会吞掉异常）——禁止这么写。
28. **C**。`AutoCloseable`（`Closeable` 是它的子接口）。资源必须可实现自动关闭，否则编译不过。
29. **B**。父类异常在前会"捕获所有"，后面的 `catch` 永远到不了 → 编译错误（unreachable catch block）。
30. **B**。重写方法抛出的异常不能比父类**更宽**（可以更窄、可以完全不抛），否则破坏多态契约。
31. **B**。`Error`（`OutOfMemoryError`、`StackOverflowError`）表示 JVM 层面的严重问题，程序无能为力，不该 `catch`。
32. **B**。多异常捕获要求类型之间**不能有继承关系**（否则子类会被父类吞掉），且 `e` 隐式为 `final`。

### 模块五

33. **B**。类型擦除：运行时 `List<String>`、`List<Integer>` 都是 `List`（泛型只在编译期检查）。
34. **B**。泛型**不变**（invariant）：`List<String>` 不是 `List<Object>` 的子类型。要兼容得用 `List<? extends Object>`。
35. **B**。`? extends` 是**上界通配符**，适合读（PECS 的 "Producer Extends"），不能 `add`（编译器不知道具体子类型）。
36. **A**。`? super` 是**下界通配符**，适合写（"Consumer Super"）；`add(Integer)` 合法，但取出的是 `Object`。
37. **C**。类型擦除后 `T` 变成 `Object`，无法 `new T()`；也不能 `new T[]`、不能 `instanceof List<String>`。
38. **B**。静态成员属于类、不属于实例，无法使用类上的泛型参数，必须在方法签名上单独声明 `<T>`。
39. **C**。`List<?>` 唯一能 `add` 的是 `null`（因为 `null` 是所有引用类型的值）；读出来只能当 `Object`。
40. **C**。泛型参数必须是引用类型，`int` 要用 `Integer`（自动装箱）。

### 模块六

41. **B**。字符流按编码解码，处理中文不乱码；`FileInputStream` 是字节流，直接读中文会得到半个字符的字节。
42. **B**。`readLine()` 返回 `null` 表示流结束（返回 `""` 表示读到空行）。
43. **A**。`FileWriter(file)` 默认覆盖，`FileWriter(file, true)` 追加。
44. **B**。缓冲流数据在内存缓冲里，不 `flush`/`close` 就不会落盘（`close` 会隐式 `flush`）。try-with-resources 能自动关。
45. **B**。`Serializable` 是**标记接口**，没有方法，只是告诉 JVM"这个类可序列化"。
46. **B**。`transient` 字段不参与序列化，反序列化后是默认值（如 `null`/0）。用于密码、连接等敏感或不可序列化字段。
47. **B**。NIO：`Channel`（双向通道）、`Buffer`（缓冲区，读写都经过它）、`Selector`（多路复用）。面向缓冲区而非流。
48. **B**。`System.out` 是 `PrintStream`（字节流，内部有编码处理），`System.err` 也是。

### 模块七

49. **A**。`Callable<V>.call()` 有返回值、可抛受检异常，配 `Future` 使用；`Runnable.run()` 无返回值。
50. **B**。`BLOCKED` = 等 `synchronized` 锁；`WAITING` = 等 `notify`/`join`/`park` 等显式唤醒（无超时）；`TIMED_WAITING` 是带超时的等待。
51. **B**。`static synchronized` 锁当前类的 `Class` 对象；非静态 `synchronized` 锁 `this`。
52. **B**。`volatile` 保证可见性（写立刻刷主存、读从主存读）+ 禁止指令重排，但 `i++` 仍非原子 → 计数必须用 `AtomicInteger` 或加锁。
53. **D**。7 个核心参数：`corePoolSize`、`maximumPoolSize`、`keepAliveTime`、`unit`、`workQueue`、`threadFactory`、`handler`。没有"优先级"。
54. **D**。四种拒绝策略：`AbortPolicy`（抛异常，默认）、`CallerRunsPolicy`（调用者线程执行）、`DiscardPolicy`（静默丢弃）、`DiscardOldestPolicy`（丢最老的）。
55. **B**。`wait()` 释放锁并进入等待队列（必须在 `synchronized` 内调用）；`sleep()` 不释放锁。这是面试必问。
56. **B**。`CountDownLatch` 是一次性的（计数到 0 不能重置）；`CyclicBarrier` 可循环复用（`reset()`）。

### 模块八

57. **D**。三种方式：`对象.getClass()`、`类名.class`、`Class.forName("全限定名")`。`new Class()` 不成立（构造器私有）。
58. **B**。`getMethod` 只拿 public 且**包含继承**的；`getDeclaredMethod` 拿本类**所有**（含 private）但**不含继承**。反射调用私有方法需 `setAccessible(true)`。
59. **C**。`RetentionPolicy`：`SOURCE`（编译丢弃）、`CLASS`（留在 class 文件，默认，运行时不可见）、`RUNTIME`（运行时可反射读取）。Spring 的注解几乎都是 `RUNTIME`。
60. **B**。`Class.newInstance()` 在 JDK 9 起标记废弃（会绕过受检异常检查），推荐 `getDeclaredConstructor().newInstance()`。

## 7. 面试一句话（今天先记住这句，D3 再展开）

> **HashMap 为什么线程不安全？**
> 因为它没有任何同步措施：JDK 1.7 采用头插法，多线程扩容时可能形成环形链表导致 CPU 100%；1.8 改成尾插法解决了成环，但仍会因为 `put` 时两个线程同时判断桶为空而覆盖数据，`size++` 也不是原子操作。所以并发场景要用 `ConcurrentHashMap`——1.8 用 `synchronized + CAS` 只锁桶头节点，而不是像 1.7 那样锁整个 Segment。
