## 三、每天怎么用这份计划

1. 早上打开本周文件，**只看今天那一行**，别一次读完。
2. 按当天"看课章节 → 动手任务 → 验收标准"的顺序做，时长达标就停，不要"再多看一点"。
3. 每天结束 `git commit` + 在 [`PROGRESS.md`](PROGRESS.md) 写 3 行日志。
   - **做完当天的练习题 = 这一天结束**。第二天跟助手说一句"dN 做完了"，助手会在讲义末尾追加「批改与点评」（得分表 + 逐题批注 + 错题回炉表），**不改动你自己填的答案**。
4. 周日：对照"自查 3 问 + 1 个术语关"口述一遍，勾掉本周打卡。
5. **遇到听不懂的名词**：先查 [Java/00-JavaSE总体路线与术语表](Java/00-JavaSE总体路线与术语表.md)，当天把卡住的 3 个词用自己的话补进去。
6. **12 月起每天多一件事**：投递 15 分钟（见 [`投递记录.md`](投递记录.md)），**面试优先于学习，投递优先于刷题**。

### 代码块规范（2026-11-17 起，所有讲义强制遵守）

写讲义时**不许出现"上面缺一半、下面接不上"的代码**。每段 Java 代码必须满足：

| 要求 | 具体做法 |
| --- | --- |
| **能直接跑** | 第一行写 `// 文件：XxxDemo.java`；`import` 齐全；有 `class`；有 `main`（或注明是被调用的类，另给调用它的 main） |
| **结果已知** | 代码块末尾用 `// 输出：` 贴出真实运行结果（多行就逐行写） |
| **上下文完整** | 需要前置代码时，把前置代码**一起写进同一个代码块**，而不是写 `// ... 前面已定义` |
| **多文件讲清** | 涉及多个类时，每个 `// 文件：X.java` 分开写，并说明编译运行顺序（`javac A.java B.java` / `java A`） |
| **片段要标注** | 极少数纯语法示意用 `// 【片段】粘到 main 里` 或 `// 【片段】粘到类里` 明确位置 |
| **禁止伪代码** | 不允许出现 `if (读取失败)`、`...`、`// 省略` 这类不可编译的占位（除非明确标成「伪代码，仅示意结构」） |

> 目的：复制 → 存文件 → 运行，中间不需要自己补任何东西。

## 四、改计划的规则

- **只在周日晚改**，周中不改计划（避免每天重新规划、实际不动手）。
- 落后 ≤2 天：周日机动时间补，当周不欠账。
- 落后 >3 天：按周文件末尾"减法清单"砍内容，**总周期不延长**。
- 换课程/换项目：先改 `README.md` 的课程表和时间线，再改对应周文件，最后改 `PROGRESS.md`（三处必须一致）。
- **12 月的特殊规则**：投递与面试 > 学习进度。面试通知一到，当天计划顺延，不许"等我学完这章再面"。
