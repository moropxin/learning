## 3. 核心知识点回顾

### 3.1 封装

封装的核心思想是：把“数据”和“操作数据的方法”放在一起，并对外隐藏实现细节。

常见例子：

- 使用 private 修饰字段
- 通过 getter 和 setter 对外暴露访问接口
- 在 setter 中检查有效性，例如 age >= 0 && age <= 150

优点：

- 增强代码安全性
- 降低耦合度
- 便于后续维护和扩展

关键理解：

- private 只能在当前类中使用
- 子类不能直接访问父类的 private 成员
- 但子类可以通过父类提供的 public / protected 方法间接访问

### 3.2 继承

继承的本质是：让子类复用父类中的属性和方法，形成“is-a”的关系。

典型理解点：

- 子类继承父类的非 private 成员
- 当创建子类对象时，父类构造器会先被调用
- 子类可以扩展父类功能，也可重写方法

常见容易混淆的点：

- private 不是“不可继承”，而是“不能直接访问”
- 继承不是复制代码，而是复用父类的逻辑结构

### 3.3 多态

多态的核心是：同一个方法调用会根据对象实际类型执行不同的实现。

例如：

- 父类引用指向子类对象
- 调用父类方法时，实际执行的是子类覆盖后的方法

常见场景：

- 抽象类与接口的实现类
- 数组/集合中存储父类对象，而实际运行时对象不同

关键概念：

- 重载（overload）：同一个类中，参数列表不同的方法
- 重写（override）：子类覆盖父类方法
- 动态绑定：运行时决定调用哪个实现

### 3.4 访问控制与可见性

Java 中常用权限修饰符：

- public：任何类都可以访问
- protected：同包下或子类中可访问
- 默认（包级）访问：同包可见
- private：仅当前类可访问

日常使用建议：

- 字段尽量用 private
- 需要复用给子类时，可考虑 protected
- 对外提供接口时再用 public

## 5. 错题与复盘

以下内容是本日最需要回顾的几个点：

### 5.1 错点一：子类是否能直接访问父类 private 字段

错误认知：

- 之前容易以为“子类继承了父类一切成员”，忽略了 private 的限制。

正确理解：

- 子类继承的是“成员的定义和实现”，但不能直接访问 private 字段。
- 必须通过父类公开/受保护的方法来访问。

### 5.2 错点二：重载与重写混淆

错误认知：

- 容易将“参数不同的同名方法”误认为是方法重写。

正确理解：

- 重载是同一类中，同名方法参数不同
- 重写是子类覆盖父类方法

### 5.3 错点三：向下转型没有做判断

错误认知：

- 若直接强转，容易出现运行时异常。

正确理解：

- 强转前最好使用 instanceof
- 例如：if (obj instanceof Circle) {
    Circle c = (Circle) obj;
  }

### 5.4 算法错点：滑动窗口 left 移动错误

在 LeetCode 3 中，我需要特别注意：

- 不能简单写 left = lastIndex
- 正确写法应为：left = Math.max(left, lastIndex + 1)

原因：

- lastIndex 指向的是重复字符上一次出现的位置
- 窗口的左边界必须停在“重复元素后一个位置”之后

这个细节是滑动窗口题的核心难点之一。

## 6. LeetCode 3 题复盘

### 6.1 题目理解

题目要求：

- 求一个字符串中，最长无重复字符子串的长度

例如：

- 输入："abcabcbb"
- 输出：3
- 原因："abc" 为最长无重复字符子串

### 6.2 核心思路

使用滑动窗口：

- left 表示窗口起点
- right 表示窗口终点
- 使用哈希表记录字符是否已在当前窗口中
- 遇到重复字符时，移动 left
- 每次更新最大长度

### 6.3 Java 实现要点

伪代码思路：

- 初始化 Map<Character, Integer> map
- 遍历字符串
- 如果当前字符已存在并且它在窗口中：更新 left
- 更新 map 中字符的最新位置
- 维护 maxLen

### 6.4 时间复杂度分析

- 访问每个字符最多一次
- 每次更新 left 和 map 仅常数时间

所以整体复杂度为：

- 时间复杂度：O(n)
- 空间复杂度：O(min(n, charset))
