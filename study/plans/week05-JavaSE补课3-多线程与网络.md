## 六、高频坑 / 减法清单

| 坑 | 说明 |
| --- | --- |
| 直接调 `run()` | 那是普通方法调用，还是在主线程跑；必须 `start()` |
| 锁字符串常量/`Integer` | 常量池复用会让不相关的代码互相阻塞，锁必须用 `private final Object lock = new Object()` |
| `volatile` 当原子用 | 它只保证可见性+有序，`count++` 依然会丢 |
| 线程池用 `Executors` 快捷方法 | `newFixedThreadPool` 用无界队列，会 OOM；生产必须手写 `ThreadPoolExecutor` |
| `wait` 用 if 而不是 while | 虚假唤醒会出错，标准写法是 `while (条件不满足) wait();` |
| 网络编程陷太深 | 这周只要"能讲清 TCP/HTTP 概念 + 会写一个 Socket demo"，NIO/Netty 不碰 |

**减法顺序**：先砍「`Condition`」→ 再砍「`CountDownLatch`」→ 再砍 Socket demo 的 UDP 部分。**卖票 + 线程池 + HTTP 结构不能砍**，面试必问。

## 七、面试一句话

> **线程池的核心参数和工作流程？**
> 七个参数：核心线程数、最大线程数、空闲存活时间、时间单位、工作队列、线程工厂、拒绝策略。任务进来先看核心线程是否满，没满就新建核心线程；满了就进队列；队列也满了才扩到最大线程数；再满就触发拒绝策略。所以**队列类型决定了它会不会真的扩容**——用无界队列时最大线程数永远用不上，这也是 `Executors.newFixedThreadPool` 会 OOM 的原因。
