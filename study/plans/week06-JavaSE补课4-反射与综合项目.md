## 六、高频坑 / 减法清单

| 坑 | 说明 |
| --- | --- |
| 项目一上来写 UI | 先定接口和数据结构，UI 最后写；顺序反了会反复改 |
| 所有代码塞进 main | 分层不是为了好看，是为了"改一处不影响其他" |
| 反射当日常手段 | 反射破坏封装、无编译检查、慢，只在框架/工具里用 |
| 注解没写 `@Retention(RUNTIME)` | 默认 `CLASS`，运行时读不到，这是新手最常见的坑 |
| 总测分数低就慌 | 这是补完课后的检测，分数低说明要补，不是说明失败 |

**减法顺序**：先砍「动态代理」→ 再砍「项目里的日志功能」→ 再砍「反射工厂」。**分层的 dao/service/ui + 文件持久化不能砍**，这是 JavaWeb 的前置心智模型。

## 七、面试一句话

> **反射有什么用？为什么框架离不开它？**
> 反射让程序在运行时才知道"要操作哪个类、调哪个方法"——框架正是靠这个实现通用性：Spring 读注解知道要创建哪个 Bean，MyBatis 把结果集按字段名塞进对象，JUnit 找 `@Test` 方法。它的代价是绕过了编译期检查、无法内联优化，所以日常业务代码不用它，只在框架和工具层用。
